# 동아에스티 — Bio Knowledge Hub (design concept)

바이오시밀러/신약 개발 연구소(배양공정팀·정제공정팀·바이오분석팀)를 위한 과제 중심 통합
데이터 플랫폼 프로토타입. 빌드 도구 없이 파일을 열면 바로 동작합니다.

**디자인 컨셉 시안입니다.** 공유 전 [상태](#상태--무엇이-실제인가)를 먼저 확인하세요.

## 스터디 중심 데이터 통합

이 플랫폼의 통합 단위는 **과제가 아니라 스터디**입니다. 스터디가 정의되면
`스터디 → 실험 조건(Arm) → 배양 / 정제 / 분석` 사슬로 세 팀 데이터가 자동으로 묶입니다.
담당자에게 개별 요청할 필요가 없어지는 지점이 바로 이 사슬입니다.

```
ST-02  Column Binding Capacity Optimization
├─ Arm A  RT 4 min · 40 g/L   → 배양 B2402 → 정제 P2402-B → 분석 A2402-02, A2402-03
├─ Arm B  RT 6 min · 50 g/L   → 배양 B2402 → 정제 P2402-C → 분석 A2402-07
└─ Arm C  RT 8 min · 60 g/L   → 배양 B2402 → 정제 P2402-D → 분석 A2402-08
```

**대시보드에서 스터디 카드를 클릭하면** 페이지 이동 없이 모달이 열리고, 해당 조건의
세 팀 데이터가 3열 그리드로 한 화면에 나옵니다.

| 열 | 팀 | 표시 데이터 |
|---|---|---|
| 🧪 | 배양공정팀 (Upstream) | VCD · Viability · Titer · 배양 pH/DO · **DO/pH 시프트 기록** · 추이 그래프 |
| 🔬 | 정제공정팀 (Downstream) | Step Yield · **DBC** · SEC-HPLC 순도 · 체류시간/부하량 · HCP/HCD 제거 |
| 📊 | 바이오분석팀 (Analytics) | **CEX 전하 이형체** (Acidic/Main/Basic) · **Intact Mass** · **결합친화도 K_D** |

**설계상 신경 쓴 부분 세 가지:**

1. **부서별 제출 현황을 명시** — `배양 3/3 · 정제 2/3 · 분석 2/3` 처럼 표시해, 빈 열이
   "해당 없음"인지 "아직 미제출"인지 구분됩니다. 미제출이면 EBR 입력 버튼이 함께 뜹니다.
2. **원료 참조(Feed) 구분** — 정제 스터디는 배양을 수행하지 않지만 원료 배치는 부하량을
   설명하는 필수 맥락이라, "미참여"로 숨기지 않고 *참조* 로 표시합니다.
3. **OOS 귀속 분리** — 분석 전용 스터디(ST-03)가 원료로 쓴 이전 정제 런의 DBC 실패를
   자기 실패로 집계하지 않습니다. 그 실패는 컬럼을 돌린 스터디(ST-02)의 것입니다.

### 피드백 태깅

모달의 모든 지표 행에 마우스를 올리면 태그 버튼이 나타납니다. 남긴 메모는
**스터디 + 실험 조건 + 지표**에 묶여 저장되고, 다른 조건으로 전환하면 표시되지 않습니다.
그리고 이 태그는 회의 모드 회의록에 그대로 실립니다:

```
- [스터디 태그 / 동적결합용량 DBC · RT 4 min · 40 g/L] RT 4분은 DBC 규격 미달 — RT 6분 이상으로 상향 필요 (박서연)
```

별도 PPT 없이 대시보드 한 화면으로 주간 회의가 돌아가는 구조입니다.

## 회의 모드 (강조 구현)

`대시보드 → 회의 모드 시작`. 투사 환경을 전제로 크롬을 걷어내고 타이포를 키운 발표 뷰입니다.

**구성** — 5개 아젠다 섹션(과제 개요 · 배양 · 정제 · 분석 · 이슈&액션) + 자동 생성 회의록.

| 기능 | 동작 |
|---|---|
| 섹션 이동 | `→`/`Space` 다음, `←` 이전, `1`–`6` 바로가기, `Home`/`End`, 하단 필. 지나온 섹션은 ✓ 표시 |
| 발표 타이머 | 섹션별 경과 + 전체 경과. 배정 시간의 80%에서 주황, 초과 시 빨강 |
| 지표 스포트라이트 | KPI 카드를 클릭하면 선택 상태가 되고, 이후 작성하는 메모가 그 지표에 연결됨 |
| 피드백 메모 | 우측 패널에서 즉시 기록. 섹션과 지표가 함께 저장됨 (`Ctrl+Enter` 저장) |
| 액션 전환 | 메모의 `→` 버튼으로 액션 아이템 승격 — 담당자·기한 지정 |
| 회의록 | 마지막 슬라이드에서 실데이터 요약 + OOS + 메모 + 액션을 텍스트로 조립, 클립보드 복사 |
| 단축키 도움말 | `?` |

메모와 액션은 `Store`에 저장되어 회의가 끝나도 남습니다.

**자동 생성 회의록 예시** (실제 출력):

```
[DA-3880 주간 공정개발 회의]
일시: 2026-07-27 · 소요 08:12
과제: DA-3880 바이오시밀러 (자가면역) (IgG1 mAb)

■ 요약
- 배양: 최고 Titer 4.05 g/L (B2402), 배치 3건
- 정제: 최고 회수율 95.1% (MabSelect PrismA), 런 3건
- 분석: 규격 이탈 2건

■ 규격 이탈 (OOS)
- P2402-B CEX Main Peak 53.8% (규격 55–70, 2026-07-26)

■ 논의 메모
- [바이오분석 / CEX Main Peak] 용출 pH 5.6→5.8 조정 검토 필요 (박서연)

■ 액션 아이템
- [ 진행 ] 용출 pH 조정 검토 / 담당 이하은 / 기한 2026-08-05
```

## 3개 부서 워크플로우 (구현됨)

브리핑의 Step 1–4가 실제로 연결되어 동작합니다.

1. **배양** — EBR에서 배치 생성 → 일자별 기록 저장 → 캘린더에 일정 추가
2. **수확** — `수확 완료 · 정제팀 전달` → 캘린더의 *수확 예정* 이 **진행중 → 완료** 로 전환되고
   정제 런이 자동 생성되며 정제 서식으로 이동
3. **정제 → 분석 의뢰** → 분석 서식으로 이동
4. **분석** — 입력 즉시 규격 판정, 저장 시 OOS가 우측 알림·대시보드 배너에 반영
5. **회의** — 대시보드에서 3팀 데이터를 회의 모드로 검토

## 검증 결과 (브라우저 실측)

### DoE 엔진 — 실제 계산

| 항목 | 결과 |
|---|---|
| 실험 횟수 | FF 8+3=11, BBD 12+3=15, CCD 8+6+3=17 |
| CCD 회전성 α | 1.6818 = 8^(1/4) ✔ |
| 항 선택 | FF 7개(2차항 없음), BBD 10개 ✔ |
| **기지 2차모델 복원** | 계수 전부 소수점 4자리 일치, R²=1, RMSE 1.06e−15 |
| **최적점 탐색** | 해석해 대비 오차 0.025 (격자 간격 0.05 이내) |

> 2수준 요인배치는 모든 실험점에서 x²≡1 → 2차항이 절편과 공선 → XᵀX 특이행렬.
> 따라서 Full Factorial은 선형+교호작용, BBD/CCD는 완전 2차 모델로 자동 분기합니다.

### 규격 판정 · 예약 충돌

- SPEC 판정: 하한만/상한만/범위, 경계값 포함(95.0 ≥ 95 통과, 100 ≤ 100 통과), 빈값·미지 항목 `null` — 전부 정상
- 예약 충돌: 완전 중복 · **걸침(09–11 vs 10–12)** · 포함(10–11) 차단 / 인접(12–13) · 타 장비 · 타 날짜 허용 — 7개 케이스 전부 정상

**스터디 통합 단계에서 발견해 고친 설계 오류**

- **Arm 라벨과 실제 공정값 불일치** — "RT 4 min" 조건이 rt=6 인 런을 가리키고 있었습니다.
  ST-01은 컬럼 조건을 고정하고 pH만, ST-02는 원료를 고정하고 컬럼 조건만 바꾸도록
  데이터를 재구성했습니다 (교락 제거).
- **OOS 오귀속** — 분석 전용 스터디가 원료로 쓴 정제 런의 DBC 실패까지 집계했습니다.
  `study.teams`에 정제가 포함될 때만 정제 규격을 판정하도록 수정.
- **Arm 간 분석 데이터 번짐** — 같은 시료를 공유하는 분획들이 서로의 분석값을 모두
  표시했습니다. Arm에 명시된 분석 목록이 있으면 그것만 사용하도록 수정.
- **태그 메모 레이아웃 붕괴** — `.kv`에 `flex-wrap`이 없어 `flex-basis:100%`인 메모가
  한 줄에 한 단어씩 세로로 쌓였습니다.

**이전 단계에서 발견해 고친 버그**

1. **UTC 날짜 버그** — `toISOString()`은 UTC로 변환하므로 KST(UTC+9) 사용자는 매일 오전 9시까지
   *전날* 날짜를 보게 됩니다. EBR 기록일에서는 치명적이라 `Store.localISO()`로 교체했습니다.
   (확인: 로컬 2026-07-27 / UTC였다면 2026-07-26)
2. **캘린더 이벤트 덮어쓰기** — 일자별 기록 저장이 `ref` 일치로 *접종* 이벤트를 찾아 날짜를
   덮어썼습니다. `B2401#inoc` / `#harvest` / `#d8` 복합 키로 분리했습니다.
3. **이름 없는 입력 필드** — `field()` 헬퍼가 `for` 없는 `<label>`을 생성해 스크린리더가 필드명을
   읽지 못했습니다. 컨트롤을 `<label>` 안에 감싸 암시적 연결로 수정 (10/10, 9/9, 7/7 해결).
4. 회의록에 내부 키(`an-cex`)가 노출 → `CEX Main Peak` 라벨로 매핑.
5. 문헌 영문 부제 4.42:1 (확장 시 배경이 바뀜) → `mute` 단계로 상향.

그 외: 키보드 포커스 상시 표시, 건너뛰기 링크, `prefers-reduced-motion` 준수, 차트마다
`aria-label` + 화면낭독기용 데이터 표, 색만으로 의미를 전달하지 않음, 터치 타깃 44×44px.

## 상태 — 무엇이 실제인가

| | |
|---|---|
| 디자인·레이아웃·인터랙션·회의 모드 | 실제 완성 |
| **DoE 계산 / 규격 판정 / 예약 충돌** | **실제 로직** |
| 로그인 | **목업** — 브라우저 내 상수 비교 + `sessionStorage` |
| **AI 검색 — 사내 데이터** | **실제** — 질문을 해석해 실제 행을 추리고 브라우저에서 계산 (`ask-engine.js`) |
| **AI 검색 — 외부 문헌** | **실제** — Europe PMC · Crossref 공개 API 실시간 호출 (`lit-api.js`) |
| **엑셀·CSV 업로드 질의** | **실제** — 브라우저 안에서만 파싱, 서버 전송 없음 (`tables.js`) |
| 답변 문장 다듬기 | **실제(선택)** — Claude API. 키가 없으면 엔진 문장으로 자동 대체 |
| 모든 데이터 | **가상** — 과제코드·Batch·공정값·문헌 전부 시연용 |
| 브랜딩 | 동아에스티 명칭 사용, 마크는 자리표시자 |

화면에도 명시됩니다 — 상단 **샘플 데이터** 배지, 각 페이지 하단 고지, AI 응답의 데모 표기.
실제 회사명을 쓰므로 내부 제안용으로만 다뤄 주세요.

## 실제 시스템 전환 시

`INTEGRATION` 주석 지점만 교체하면 됩니다.

- **인증** (`auth.js`) — `current()` / `signIn()` / `requireSession()`.
  단, `requireSession()`은 화면을 가릴 뿐이며 **접근 제어는 반드시 서버에서** 해야 합니다.
- **데이터/영속성** (`store.js`) — `read()` / `write()` 를 API 호출로 교체하면 구독자는 그대로 동작합니다.
- **AI 검색 항목 사전** (`ask-engine.js`의 `ALIAS`) — 실제 컬럼명·현장 용어를 추가하면
  그만큼 인식 범위가 넓어집니다. 원본에 없는 항목은 `NOT_RECORDED` 에 두어
  "기록 없음"으로 답하게 합니다 — 값을 지어내지 않는 것이 이 화면의 전제입니다.
- **규격 기준** (`lab.js`의 `SPECS`) — 실제 규격서 값으로 교체하면 판정 로직은 그대로.

## 배포 (Vercel)

빌드 단계가 없는 정적 사이트입니다. 사이트는 저장소 루트가 아니라
`donga-st-bio-hub/` 안에 있고 **저장소 루트에는 `index.html` 이 없습니다.**
루트를 그대로 배포하면 `/` 가 404 가 되므로, `vercel.json` 을 두 곳에 두었습니다.

| 실행 위치 | 적용되는 설정 |
|---|---|
| 저장소 루트 (기본) | `../vercel.json` — `outputDirectory: "donga-st-bio-hub"` 로 하위 폴더를 서빙 |
| `donga-st-bio-hub/` (Root Directory 를 여기로 지정) | 이 폴더의 `vercel.json` |

둘 다 같은 헤더를 갖고 있어 어느 쪽으로 배포해도 결과가 같습니다.
Vercel 은 **배포 루트의 `vercel.json` 하나만** 읽습니다 — 나머지 하나는 무시됩니다.

```
npm i -g vercel
vercel            # 저장소 루트에서 · 프리뷰 배포
vercel --prod     # 확정 후 프로덕션
```

첫 실행 시 프로젝트를 새로 만들 것인지 묻습니다. 프레임워크는 **Other**,
빌드 명령과 출력 디렉터리는 **비워 둡니다** (`vercel.json` 이 지정합니다).

`Batch_Data_example.xlsx` 는 루트 `.vercelignore` 로 업로드에서 제외됩니다.

### AI 답변 문장 다듬기 (선택)

`api/narrate.js` 는 조회가 끝난 **값만** Claude 에 넘겨 문장을 다듬는 Serverless
Function 입니다. 수치 계산과 데이터 조회는 전부 브라우저에서 끝나므로, 이 기능이
없어도 검색은 그대로 동작합니다.

- 켜려면: Vercel 프로젝트 → **Settings → Environment Variables** → `ANTHROPIC_API_KEY`
- 끄려면: 환경변수를 두지 않으면 됩니다. 라우트가 503 을 돌려주고 화면은
  엔진이 만든 문장을 그대로 씁니다 (오류 표시 없음).
- **저장소 루트에서 배포해야 `api/` 가 함께 올라갑니다.** Root Directory 를
  `donga-st-bio-hub` 로 지정하면 이 라우트는 배포되지 않고, 문장 다듬기만 빠집니다.

`vercel.json` 이 하는 일:

- **`X-Robots-Tag: noindex`** — 각 페이지의 `meta robots` 는 HTML 에만 걸립니다.
  실제 회사명을 쓰는 프로토타입이므로 JS·CSS·이미지까지 헤더로 덮습니다.
- **`Cache-Control: no-cache`** (html/css/js) — 파일 이름에 해시가 붙지 않아
  캐시를 허용하면 재배포 후에도 옛 CSS·JS 가 남습니다.

주의: 프로덕션 URL 은 기본적으로 **누구나 접근 가능**합니다. 사내 자료이므로
프리뷰 배포로 두고 프로젝트 설정의 **Deployment Protection** (Vercel Authentication)
을 켜는 편이 안전합니다 (적용 범위는 요금제에 따라 다름).

## 알려진 한계
