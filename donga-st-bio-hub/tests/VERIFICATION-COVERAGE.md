# 수치 검증 적용 범위

AI 검색이 사용자에게 내보내는 문장에 근거 없는 숫자가 실리지 않도록 하는
장치의 적용 범위입니다. 회귀 검사군 **K**(서술) 와 **O**(엔진 응답) 가 이
문서의 내용을 실제로 검사합니다.

## 두 가지 검증은 성격이 다릅니다

| | 대상 | 무엇을 막나 | 허용집합 | 위반 시 |
|---|---|---|---|---|
| **서술 검증**<br>`checkNarration` | `/api/narrate` 가 다듬은 문장 (LLM 작성) | 모델이 **지어낸** 숫자 | 조회 결과 객체 | 문장을 버리고 엔진 원문 사용 |
| **응답 검증**<br>`checkResult` | 엔진이 만든 모든 문장 | 코드 버그로 **엉뚱한 값**이 실림 | 데이터에서 다시 계산 | 문장을 템플릿으로 대체 |

응답 검증의 허용집합을 결과 객체가 아니라 **데이터에서 유도**하는 것이
핵심입니다. 엔진 문장을 엔진 문장과 대조하면 자기 자신과 비교하는 셈이라
무엇이든 통과합니다.

허용하는 값: 표의 모든 셀과 날짜(연·월·일 포함) · 조회 범위와 전체에 대해
다시 계산한 통계(n·평균·중앙값·표준편차·최소·최대·합·CV) · 그룹별 평균과
그 차이(절대·%) · 구조적인 수(행·컬럼·과제·Study·배열 길이·기록 건수) ·
질문에 사용자가 쓴 숫자와 파서가 읽은 조건값 · 배양 경과일 라벨과 일자별 값.

## 경로별 적용 현황

전 경로 적용 완료입니다. 검사군 O 가 경로마다 정상 응답 통과(거짓 차단 없음)와
변조 검출(headline · hints · warnings)과 템플릿 대체를 확인합니다.

| 응답 경로 | 숫자 포함 | 검증 | 비고 |
|---|:---:|:---:|---|
| extreme (최고·최저) | O | O | |
| stat (통계) | O | O | |
| list (목록·조건) | O | O | |
| compare (비교) | O | O | 그룹별 평균과 차이(%)까지 |
| trend (일자별 추이) | O | O | 경과일 값 포함 |
| missing (결측) | O | O | |

## 검증하지 않는 것과 그 이유

| 대상 | 이유 | 위험도 |
|---|---|---|
| 외부 문헌 결과 (Europe PMC · Crossref) | 사내 데이터가 아니라 원문 그대로 싣는 인용입니다. 제목·저자·DOI 를 그대로 보여 주며 우리가 수치를 계산하지 않습니다. | 낮음 — 지어낼 여지가 없음 |
| 대시보드 · EBR · 회의 모드 차트의 수치 | AI 검색 응답이 아니라 화면이 데이터를 직접 렌더링한 것입니다. 값이 표에서 바로 나오므로 문장 검증의 대상이 아닙니다. | 낮음 |
| 개발 모드 디버그 패널의 소요 시간 · 토큰 수 | 데이터가 아니라 계측값입니다. 데이터셋과 대조할 성질이 아닙니다. | 낮음 — 개발 모드에서만 보임 |
| 업로드한 표(kind=upload)에 대한 응답 | 검증은 동작하지만 허용집합이 그 표에서만 만들어집니다. 원본 Excel 앵커가 없어 "테이블 생성이 통째로 틀어진" 경우는 잡지 못합니다. | 중간 — 사용자가 올린 파일이므로 원본과 대조할 기준이 없음 |

## 알려진 한계

* 응답 검증은 **엔진이 자기 데이터로부터 계산한 값과 다른 값을 썼는가** 를 봅니다.
  엔진이 *잘못된 행을 골라* 그 행의 진짜 값을 정확히 인쇄하면 통과합니다.
  그런 종류의 오류는 검사군 A~I 의 건수·범위 단언이 담당합니다.
* 허용집합이 넓어질수록 검출력이 떨어집니다. 지금은 질문 125개 · 수치 5,114개에서
  거짓 차단 0건이고, 삽입한 이물 수치는 전부 잡습니다. 허용 항목을 늘릴 때는
  이 두 수치를 함께 확인해야 합니다.
* 검증 부품(`numbersIn` · `visibleStrings` · `allowedFrom`)은 `AskVerify._parts` 로
  바꿔 끼울 수 있게 두었습니다. 변이 검사가 실제로 동작을 바꿀 수 있어야
  "보호되고 있다" 를 증명할 수 있기 때문입니다.
