# 중앙 서버 데이터베이스 설정 안내

이 문서대로 하면 데이터가 브라우저에서 **중앙 DB** 로 옮겨 갑니다. 그때부터
다른 PC·다른 사람이 같은 데이터를 봅니다.

설정 전까지는 지금처럼 각자 브라우저에 저장됩니다 — 설정이 늦는다고 사이트가
멈추지는 않습니다.

---

## 1. Vercel 에 Postgres 붙이기

1. Vercel 대시보드 → 이 프로젝트 → **Storage** 탭
2. **Create Database** → **Postgres** (Neon) 선택
3. 지역은 가까운 곳(예: Singapore / Tokyo)
4. **Connect to Project** 로 이 프로젝트에 연결

연결하면 `POSTGRES_URL` 을 비롯한 환경변수가 **자동으로 주입**됩니다.
직접 복사해 넣을 필요가 없습니다.

표(`records` · `entry_values` · `meta`)는 첫 요청에서 서버가 알아서 만듭니다.

---

## 2. 접속 비밀값 넣기

Vercel 대시보드 → **Settings → Environment Variables** 에서 하나 추가합니다.

| 이름 | 값 | 적용 환경 |
|---|---|---|
| `HUB_ACCESS_SECRET` | 팀이 쓸 접속 비밀번호 (16자 이상 권장) | Production · Preview |

**이 값을 지금 로그인 화면에서 쓰는 비밀번호와 같게 두세요.** 로그인할 때
같은 값을 서버에도 보내 쿠키를 받습니다. 입력란을 둘로 늘리지 않으려는
것입니다.

> 비밀값은 이 문서나 코드, 채팅 어디에도 적지 마세요. Vercel 환경변수에만
> 두면 됩니다.

### 환경변수 정리

| 이름 | 누가 넣나 | 무엇에 쓰나 |
|---|---|---|
| `POSTGRES_URL` | Vercel 이 자동 주입 | 데이터베이스 연결 |
| `HUB_ACCESS_SECRET` | **직접 넣어야 합니다** | API 접근 통제 |
| `ANTHROPIC_API_KEY` | 이미 쓰던 것 (선택) | Global AI |

---

## 3. 재배포

환경변수를 넣은 뒤 **Redeploy** 합니다. 환경변수는 빌드 시점에 묶이므로
넣기만 하고 재배포하지 않으면 서버가 계속 못 봅니다.

---

## 4. 확인

브라우저에서 아래를 열어 봅니다.

```
https://<배포주소>/api/session
```

| 응답 | 뜻 |
|---|---|
| `{"configured":true,"signedIn":false}` | 비밀값 설정됨 · 아직 로그인 전 (정상) |
| `{"configured":false,...}` | `HUB_ACCESS_SECRET` 이 없습니다 |

로그인한 뒤 개발자 도구 콘솔에서:

```js
HubBoot.note()
```

| 결과 | 뜻 |
|---|---|
| `{mode:"server", serverReady:true}` | **서버 연결됨.** localStorage 를 쓰지 않습니다 |
| `{mode:"local", reason:"서버 미설정"}` | 1·2번이 아직 안 됐습니다 |
| `{mode:"local", reason:"로그인 필요"}` | 비밀번호가 `HUB_ACCESS_SECRET` 과 다릅니다 |

---

## 5. 처음 열 때

서버 DB 가 비어 있으면, **처음 접속한 브라우저가 원본 Excel 씨앗(28배치)을
한 번 올립니다.** 그 뒤로는 올리지 않습니다.

씨앗을 서버에서 만들지 않는 이유는, 씨앗을 만드는 코드가 이미 브라우저에
있고 검증도 되어 있기 때문입니다. 서버에서 다시 만들면 두 벌이 되고 언젠가
한쪽만 고쳐집니다.

---

## 6. 서버 데이터 초기화

두 가지 방법이 있습니다.

**화면에서** — 상단 내보내기 아이콘 → `기본 데이터로 초기화` → 지울 항목 선택

**API 로** (로그인한 브라우저에서 콘솔)

```js
await fetch('/api/data', { method: 'DELETE', credentials: 'same-origin' })
```

비우기만 합니다. 다음 접속에서 씨앗이 다시 심깁니다.
**되돌릴 수 없으니 먼저 내보내기로 한 벌 받아 두세요.**

---

## API 요약

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| `GET` | `/api/session` | 설정·로그인 상태 |
| `POST` | `/api/session` | `{secret}` 로 로그인 → 쿠키 발급 |
| `DELETE` | `/api/session` | 로그아웃 |
| `GET` | `/api/data` | 전체 스냅샷 (레코드·값·meta) |
| `POST` | `/api/data` | 변경 적용 `{values, records, meta}` |
| `POST` | `/api/data?seed=1` | 비어 있을 때만 씨앗 |
| `DELETE` | `/api/data` | 전부 비우기 |

`/api/data` 는 전부 쿠키가 있어야 합니다. 없으면 `401` 입니다.

---

## 알아 두실 것

- **이것은 "팀이 같은 암호를 나눠 쓰는" 수준입니다.** 누가 고쳤는지를 서버가
  증명하지는 못합니다 (화면에 적히는 작성자는 클라이언트가 보낸 값입니다).
  사람별 계정이 필요해지면 그때 올려야 합니다.
- Vercel 서버리스는 파일을 저장할 수 없습니다. SQLite 파일이나 JSON 파일
  방식은 저장한 것처럼 보이다가 다음 요청에서 사라집니다 — 그래서 관리형
  Postgres 를 씁니다.
- 다른 사람이 바꾼 것은 20초마다, 그리고 창으로 돌아올 때 받아옵니다.
