# 중앙 서버 데이터베이스 설정 안내

이 문서대로 하면 데이터가 브라우저에서 **중앙 DB** 로 옮겨 갑니다. 그때부터
다른 PC·다른 사람이 같은 데이터를 봅니다.

설정 전까지는 지금처럼 각자 브라우저에 저장됩니다 — 설정이 늦는다고 사이트가
멈추지는 않습니다.

---

## 1. Vercel 에 Postgres 붙이기

1. Vercel 대시보드 → 이 프로젝트 → **Storage** 탭
2. **Create Database** → **Postgres** (Neon) 선택
3. 지역은 가까운 곳(예: Singapore / Tokyo)
4. **Connect to Project** 로 이 프로젝트에 연결

연결하면 `POSTGRES_URL` 을 비롯한 환경변수가 **자동으로 주입**됩니다.
직접 복사해 넣을 필요가 없습니다.

표(`records` · `entry_values` · `meta`)는 첫 요청에서 서버가 알아서 만듭니다.

---

## 2. 접속 비밀값 넣기

Vercel 대시보드 → **Settings → Environment Variables** 에서 하나 추가합니다.

| 이름 | 값 | 적용 환경 |
|---|---|---|
| `HUB_ACCESS_SECRET` | 팀이 쓸 접속 비밀값 — **16자 이상 (필수)** | Production · Preview |

**16자는 권장이 아니라 필수입니다.** 더 짧으면 서버가 아예 받지 않고
`/api/session` 이 `{"configured":false,"reason":"secret-too-short"}` 를
돌려줍니다.

**이 값은 로그인 화면의 비밀번호와 달라야 합니다.** 로그인 비밀번호는
`assets/js/data.js` 안에 있고 그 파일은 사이트를 여는 누구에게나 내려갑니다
(로그인 화면에 아예 적혀 있습니다). 그 값으로 서버를 지키면 페이지 소스를
열어 본 사람 누구나 데이터에 닿습니다.

그래서 로그인 화면에 입력란이 하나 더 있습니다 — **서버 접속 비밀값**.
서버가 켜져 있을 때만 나타나고, 한 번 넣으면 쿠키가 12시간 유효하므로
매번 묻지 않습니다.

> 비밀값은 이 문서나 코드, 채팅 어디에도 적지 마세요. Vercel 환경변수에만
> 두면 됩니다.

### 환경변수 정리

| 이름 | 누가 넣나 | 무엇에 쓰나 |
|---|---|---|
| `POSTGRES_URL` | Vercel 이 자동 주입 | 데이터베이스 연결 |
| `HUB_ACCESS_SECRET` | **직접 넣어야 합니다** | API 접근 통제 |
| `ANTHROPIC_API_KEY` | 이미 쓰던 것 (선택) | Global AI |

---

## 3. 재배포

환경변수를 넣은 뒤 **Redeploy** 합니다. 환경변수는 빌드 시점에 묶이므로
넣기만 하고 재배포하지 않으면 서버가 계속 못 봅니다.

---

## 4. 확인

브라우저에서 아래를 열어 봅니다.

```
https://<배포주소>/api/session
```

| 응답 | 뜻 |
|---|---|
| `{"configured":true,"db":true,"signedIn":false}` | 둘 다 됨 · 아직 로그인 전 (정상) |
| `reason:"secret-missing"` | `HUB_ACCESS_SECRET` 이 없습니다 |
| `reason:"secret-too-short"` | 넣었지만 16자 미만입니다 |
| `"db":false` | Postgres 가 안 붙었습니다 (1번) |

`configured` 가 `false` 면 **재배포를 했는지** 먼저 보세요. 환경변수는 빌드
시점에 묶이므로, 넣기만 하고 재배포하지 않으면 서버가 계속 못 봅니다.

화면 오른쪽 위에도 지금 어디를 읽고 있는지 뱃지로 나옵니다.

| 뱃지 | 뜻 |
|---|---|
| **서버** | 중앙 DB · 다른 PC 와 같은 데이터 |
| **이 브라우저** | 서버가 꺼져 있음 · 나만 보는 데이터 |
| **서버 미연결** | 서버는 켜져 있는데 이 브라우저가 연결 안 됨 → 다시 로그인 |
| **서버 끊김** | 읽지 못했음 · 지금 값이 최신이 아닐 수 있음 |

로그인한 뒤 개발자 도구 콘솔에서:

```js
HubBoot.note()
```

| 결과 | 뜻 |
|---|---|
| `{mode:"server", serverReady:true}` | **서버 연결됨.** localStorage 를 쓰지 않습니다 |
| `{mode:"local", reason:"서버 미설정"}` | 1·2번이 아직 안 됐습니다 |
| `{mode:"local", reason:"로그인 필요"}` | 로그인할 때 '서버 접속 비밀값' 을 넣지 않았거나 틀렸습니다 |

## 5. 처음 열 때

서버 DB 가 비어 있으면, **처음 접속한 브라우저가 원본 Excel 씨앗(28배치)을
한 번 올립니다.** 그 뒤로는 올리지 않습니다.

씨앗을 서버에서 만들지 않는 이유는, 씨앗을 만드는 코드가 이미 브라우저에
있고 검증도 되어 있기 때문입니다. 서버에서 다시 만들면 두 벌이 되고 언젠가
한쪽만 고쳐집니다.

---

## 6. 서버 데이터 초기화

두 가지 방법이 있습니다.

**화면에서** — 상단 내보내기 아이콘 → `기본 데이터로 초기화` → 지울 항목 선택

**API 로** (로그인한 브라우저에서 콘솔)

```js
await fetch('/api/data', { method: 'DELETE', credentials: 'same-origin' })
```

비우기만 합니다. 다음 접속에서 씨앗이 다시 심깁니다.
**되돌릴 수 없으니 먼저 내보내기로 한 벌 받아 두세요.**

---

## API 요약

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| `GET` | `/api/session` | 설정·로그인 상태 |
| `POST` | `/api/session` | `{secret}` 로 로그인 → 쿠키 발급 |
| `DELETE` | `/api/session` | 로그아웃 |
| `GET` | `/api/data` | 전체 스냅샷 (레코드·값·meta) |
| `POST` | `/api/data` | 변경 적용 `{values, records, meta}` |
| `POST` | `/api/data?seed=1` | 비어 있을 때만 씨앗 |
| `DELETE` | `/api/data` | 전부 비우기 |

`/api/data` 는 전부 쿠키가 있어야 합니다. 없으면 `401` 입니다.

---

## 알아 두실 것

- **이것은 "팀이 같은 암호를 나눠 쓰는" 수준입니다.** 누가 고쳤는지를 서버가
  증명하지는 못합니다 (화면에 적히는 작성자는 클라이언트가 보낸 값입니다).
  사람별 계정이 필요해지면 그때 올려야 합니다.
- Vercel 서버리스는 파일을 저장할 수 없습니다. SQLite 파일이나 JSON 파일
  방식은 저장한 것처럼 보이다가 다음 요청에서 사라집니다 — 그래서 관리형
  Postgres 를 씁니다.
- 다른 사람이 바꾼 것은 20초마다, 그리고 창으로 돌아올 때 받아옵니다.

## 7. E2E 검사

로그인해 서버에 연결한 뒤 엽니다.

```
https://<배포주소>/ops/e2e-server.html
```

여섯 그룹을 봅니다 — 서버·DB 연결 / 영속성(쓰기→DB→읽기) / 다중 PC 공유 /
저장 실패 시 롤백 / 화면 연동(SSOT) / 흔적 치우기.

쓰기는 `batch:__E2E__` (어느 화면에도 없는 범위) 와 실제 배치의 추가 열
`ws_E2E검사` 하나뿐이고, 끝나면 DB 와 메모리 양쪽에서 지웁니다.
**원본 Excel 항목은 읽기만 합니다. 씨앗 심기와 전체 비우기는 돌리지 않습니다.**

돌릴 수 없었던 항목은 통과도 실패도 아닌 **`??` (UNKNOWN)** 으로 적습니다.
확인하지 못한 것을 통과로 적으면 검사가 거짓말을 하게 됩니다.

## 무엇이 공유되나

| 데이터 | 어디에 |
|---|---|
| 측정값 · Study · 시료 · 이름 변경 · 직접 추가한 항목 | **중앙 DB** |
| 일정 · 이슈 · 의뢰 · 할 일 · 회의 기록(핀·메모·안건) · 장비 예약 | **중앙 DB** |
| 개발 플래그(`hub.dev`) · AI 응답 캐시 · 화면 보기 설정 | 이 브라우저 |
| **아직 저장하지 않은 입력값** · 아직 만들지 않은 열 | 이 브라우저 |

각 화면 아래에 지금 어디에 저장되는지 한 줄로 적혀 있습니다. 상태를 읽어
적으므로, 서버가 꺼져 있으면 꺼져 있다고 말합니다.

### Data 입력은 [전체 저장] 을 눌러야 올라갑니다

표에 적은 값은 **이 브라우저에 머물다가** [전체 저장] 에서 한 번에 DB 로
갑니다. 그전에는 다른 PC 에 보이지 않습니다. 버튼 옆에 저장하지 않은 칸이
몇 개인지 늘 적혀 있고, 저장 전 칸은 파란 테두리로 구분됩니다.

탭을 닫아도 적던 내용은 그 브라우저에 남아 있다가 다시 열면 그대로 나옵니다.
다만 **다른 PC 에서는 보이지 않습니다** — 저장 전이기 때문입니다.

### 표의 열 하나가 시료 하나

[시료 추가 →] 로 열을 늘리면 시료가 하나 늘고, 머리글을 고치면 그 시료의
이름이 바뀝니다. 열에 값을 하나도 적지 않으면 아무것도 만들어지지 않습니다.

열을 지우면 그 시료가 **비활성**이 됩니다 — 값과 변경 이력은 그대로 남고,
표 위 [비활성 시료] 에서 되살릴 수 있습니다.

화면에 "Batch" 라는 말은 없습니다. 값을 담는 그릇은 시료마다 하나씩 자동으로
붙고 사용자에게는 보이지 않습니다.

### 변경 이력은 저장된 뒤부터

처음 적을 때는 이력이 남지 않습니다. 사유도 묻지 않습니다. **저장된 값을
고칠 때만** 사유를 받고 이전 값을 이력으로 쌓습니다 (ALCOA+).

옮겨 적는 동안의 오타까지 이력에 쌓으면, 나중에 "이 값이 왜 바뀌었나" 를
되짚을 때 진짜 정정 한 건이 오타 열 건에 묻힙니다.

### 목록형은 레코드 한 줄씩

일정 · 이슈 · 의뢰 · 할 일 · 회의 기록 · 예약은 측정값과 달리 `records` 표에
**한 줄씩** 들어갑니다. 덩어리로 주고받으면 이렇게 됩니다.

```
A 가 이슈를 추가 → 올림
B 가 (A 것을 아직 못 받은 채) 이슈를 추가 → 올림
→ B 의 목록이 A 의 목록을 통째로 덮어 A 의 이슈가 사라짐 (오류도 안 남)
```

그래서 **지울 때도 줄을 없애지 않고 `deleted` 를 세웁니다.** 실제로 지우면,
아직 받아 가지 못한 다른 브라우저가 다음 저장에서 그것을 되살립니다.
화면에는 나오지 않지만 기록은 남습니다.

### 장비 예약

예전에는 `Store` 가 사용자 이메일마다 따로 저장되어 **남의 예약이 아예 보이지
않았습니다.** 그래서 겹침 검사가 늘 "안 겹친다" 고 답했고, 두 사람이 같은
장비를 같은 시간에 잡아도 아무도 몰랐습니다. 이제 한곳에 모이므로 검사가
성립합니다. 기존 예약은 버리지 않고 서버 목록에 얹습니다.

## 8. 스냅샷 백업 · 복원 · 초기화

```
https://<배포주소>/ops/backup.html
```

로그인한 상태에서만 동작합니다 (쿠키가 없으면 서버가 401 로 막습니다).

| 하는 일 | 설명 |
|---|---|
| **스냅샷 내려받기** | DB 전체를 `backup_snapshot_<시각>.json` 한 파일로 |
| **파일로 복원** | 그 파일 시점으로 100% 되돌림 |
| **DB 비우기** | 전부 비움 — **스냅샷을 먼저 받아야 눌립니다** |

**복원하면 지금 DB 를 전부 비우고 파일 내용으로 채웁니다.** 그 전에
`backup_before_restore_<시각>.json` 을 자동으로 한 벌 더 내려받습니다 —
복원이 잘못되었을 때 돌아올 자리가 없으면 안 되기 때문입니다.

> 내려받은 파일에는 실험 데이터 전체가 들어 있습니다. 사외로 내보내지 마세요.

### 예시 Study 는 더 이상 나오지 않습니다

예전에는 `Media screening test` · `DoE test` · `Feasibility test` 세 개가
코드에 박혀 있어서, **DB 를 비운 직후에도** 드롭다운에 떠 있었습니다.
사용자가 만든 Study 와 섞여 어느 것이 자기 데이터인지 구분할 수 없었습니다.

이제 Study 목록은 **만든 것만** 보여 줍니다. 하나도 없으면
`등록된 Study 없음 — [+ 새 Study] 로 만드세요` 라고 적힙니다.

예시 한 벌(3 Study · 28 Batch · 31 시료)은 검사 스위트의 고정 입력으로
남아 있습니다. 검사는 늘 같은 입력에서 같은 답이 나와야 하기 때문입니다.
검사 페이지만 `window.HUB_EXCEL_FIXTURE = true` 를 올리고, 화면을 띄우는
페이지는 올리지 않습니다 — `tests/` 는 배포에서도 제외됩니다.

### 예시 엑셀 데이터를 다시 보고 싶다면

화면을 열기 **전에** 콘솔에서 두 줄 두고 새로 고칩니다. 앞 줄은 예시를
메모리에 싣고, 뒤 줄은 그것을 빈 DB 에 심습니다.

```js
window.HUB_EXCEL_FIXTURE = true; window.HUB_SEED_EXCEL = true
```

깃발 하나만 올리면 아무 일도 일어나지 않습니다 — 실을 것이 없거나,
실었어도 심지 않습니다.

> 이미 DB 에 들어가 있는 예시는 코드를 고쳐도 사라지지 않습니다.
> `/ops/backup.html` 에서 ① 스냅샷 내려받기 → ② DB 비우기 로 지웁니다.
